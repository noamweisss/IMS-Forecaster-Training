# Handoff prompt — Translate a module to Hebrew (dual-agent)

Copy everything below the line into a fresh agent session opened on
this repo. The session uses **two agents in parallel** in Antigravity's
Manager view: a translator and an editor. The same flow works in Claude
Code (or any single-agent IDE) by running the two steps sequentially in
one session — see the fallback at the bottom.

Expected runtime: ~30–45 minutes of agent work plus whatever Antigravity's
inference takes.

---

I'm handing off translation of **Module N** of the IMS Aviation Weather
Forecasting Certification course into Hebrew. The module has already
been authored in English by the existing pipeline; everything you need
is in `courses/aviation-weather/module-N/`. Your job is to produce the
Hebrew counterpart in `courses/aviation-weather/module-N-he/` using two
agents.

## Setup (one-time per module)

1. **Open the repo in Antigravity.** Switch to **Manager view**.
2. **Create two agents:**
   - **Agent A — translator.** Use whatever capable model is available
     in your environment. This agent runs the `translator` skill at
     `.agents/skills/hebrew-translation/translator/`.
   - **Agent B — editor.** Use whatever capable model is available in
     your environment. This agent runs the `editor` skill at
     `.agents/skills/hebrew-translation/editor/`.
3. **Confirm both agents have read access to the whole repo.** They
   need to read `docs/hebrew_translation_spec.md`,
   `docs/hebrew_glossary.md`, `docs/lesson_spec.md`, and the entire
   module folder.

## Phase 1 — Translator (Agent A)

Paste this into Agent A's chat:

> Read `docs/hebrew_translation_spec.md`, then `docs/hebrew_glossary.md`,
> then `docs/lesson_spec.md` (in that order). Then translate
> `courses/aviation-weather/module-N` into Hebrew at
> `courses/aviation-weather/module-N-he/`, following the spec exactly.
>
> Hard rules (also in the spec):
> - Preserve all HTML structure, CSS class names, hex codes, SVG
>   attributes, CDATA wrappers, quiz `<name>` labels, and `fraction=`
>   markers byte-for-byte.
> - Add `dir="rtl" lang="he"` to every `.ims-lesson` wrapper.
> - Copy `module_structure.json` and `_extraction.json` verbatim.
> - Do **not** produce `README.md`, `IMAGES_TO_SOURCE.md`, or
>   `module_combined_moodle.html`. Those are regenerated by
>   `pipeline/finalize_module.py` after you finish.
> - Write `_translation_manifest.json` last.
>
> When done, tell me: files translated, glossary additions proposed,
> warnings.

Wait for Agent A to finish. Spot-check the output: open one Hebrew
lesson in a browser preview to confirm the `<style>` block survived,
the `dir="rtl"` is on the wrapper, and Hebrew renders right-to-left.

## Phase 2 — Deterministic validator (optional preflight)

Run the Python validator from a shell:

```bash
python pipeline/validate_translation.py \
    --source-module      courses/aviation-weather/module-N \
    --translation-module courses/aviation-weather/module-N-he
```

This writes (or augments) `courses/aviation-weather/module-N-he/review.json`
with deterministic findings only: structural parity, hex preservation,
CSS class preservation, CDATA integrity, RTL markers present. No LLM
involved. Exit code 1 if it found any `error`-severity issues.

If validator output reveals structural problems, fix in Agent A before
proceeding — these are mechanical failures the editor can't help with.

## Phase 3 — Editor (Agent B)

Paste this into Agent B's chat:

> Read `docs/hebrew_translation_spec.md`, then `docs/hebrew_glossary.md`.
> Then read `courses/aviation-weather/module-N-he/_translation_manifest.json`
> to see what the translator did.
>
> Compare `courses/aviation-weather/module-N` (English) and
> `courses/aviation-weather/module-N-he` (Hebrew) side by side. Run all
> 12 checks from your skill. Augment the existing `review.json` (do not
> overwrite the Python-produced entries; append yours).
>
> Hard rules: read-only on Hebrew files. Never modify any lesson, quiz,
> or manifest. Never translate text yourself, even as a "suggested fix"
> — describe the fix in English, let the translator produce Hebrew.
>
> When done, tell me: error / warning / info counts and the top three
> issues by severity.

## Phase 4 — Address issues

Open `courses/aviation-weather/module-N-he/review.json`. Sort by
severity: `error` first, then `warning`, then `info`.

- **For `error`s** — re-run Agent A scoped to the specific files
  flagged. Paste the relevant `review.json` issues into Agent A and
  ask it to regenerate just those files.
- **For `warning`s** — judgement call. Glossary inconsistencies and
  missing RTL markers usually warrant a re-run; minor SVG label gaps
  can wait until v2.
- **For `info`s** — safe to ignore for v1.

After any re-run by Agent A, re-run Phase 2 (validator) and Phase 3
(Agent B) to refresh `review.json`. The agents always overwrite live
files and archive prior versions under `.archive/`.

## Phase 5 — Finalize for Moodle

Once `review.json` has zero `error`s:

```bash
python pipeline/finalize_module.py --module courses/aviation-weather/module-N-he
```

This regenerates `module_combined_moodle.html`, `README.md`, and
`IMAGES_TO_SOURCE.md` from the Hebrew tree. The script is content-agnostic
— it doesn't care that the lessons are in Hebrew. Output is a Hebrew
Moodle-ready bundle in the same shape as the English one.

## Phase 6 — Upload

Follow `courses/aviation-weather/module-N-he/README.md`. Same two-click
Moodle workflow as the English module:
1. Paste `module_combined_moodle.html` into a new Moodle Page activity.
2. Import `module_quiz_all_questions.xml` into the Moodle question
   bank, then create a Quiz activity drawing from it.

Verify in Moodle's preview: Hebrew renders right-to-left, the correct
answer on each quiz question is the Hebrew translation of the English
correct answer, and the rationale (`generalfeedback`) is Hebrew.

---

## When you're done

Tell me:
1. Module number and number of lessons translated.
2. Final `review.json` summary (error / warning / info counts).
3. Whether `module_combined_moodle.html` was successfully regenerated.
4. Any glossary additions proposed in
   `_translation_manifest.json`'s `new_glossary_proposals` — I want to
   review these with Evgeny before they get locked in.

## Fallback — single-agent flow (Claude Code or other IDE)

If you're not in Antigravity, run the same two skills sequentially in
one session:

```
Phase 1: invoke .agents/skills/hebrew-translation/translator/SKILL.md
         (single Claude agent, same prompt as Phase 1 above)

Phase 2: python pipeline/validate_translation.py ...

Phase 3: invoke .agents/skills/hebrew-translation/editor/SKILL.md
         (same agent, fresh context window if possible — pretend to
         be a different reviewer to keep the audit trail honest)
```

Everything else (phases 4–6) is identical.
