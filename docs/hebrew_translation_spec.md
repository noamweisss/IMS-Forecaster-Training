# Hebrew Translation Specification

This document defines exactly what a translation pipeline must produce when
converting a finalized English module into Hebrew. Companion to
[lesson_spec.md](lesson_spec.md) (which defines the English output contract)
and [hebrew_glossary.md](hebrew_glossary.md) (the bilingual term list).

The pipeline is a two-agent flow designed for Google Antigravity:
1. A **Claude translator agent** reads the English module and produces a
   Hebrew counterpart with RTL adjustments.
2. A **Gemini editor agent** reviews the result and writes a structured
   `review.json` — review-only, no edits to translated files.

Both agents read this spec as their source of truth. The same spec also
serves the Python validator in [pipeline/validate_translation.py](../pipeline/validate_translation.py).

---

## What you produce, per module

```
courses/<course>/module-N-he/
├── 00_module_overview_moodle.html        ← translated body fragment
├── module_structure.json                  ← copied verbatim (English, internal)
├── _extraction.json                       ← copied verbatim (English, internal)
├── _translation_manifest.json             ← written by translator agent
├── review.json                            ← written by editor agent (after translation)
├── lessons/
│   ├── 01_<slug>_moodle.html              ← translated, English slug retained
│   ├── 01_<slug>_quiz.xml                 ← translated CDATA text only
│   ├── 02_<slug>_moodle.html
│   ├── 02_<slug>_quiz.xml
│   └── ...
│   └── Images/                            ← copied or symlinked from English module
```

Do **not** produce: `README.md`, `IMAGES_TO_SOURCE.md`, or
`module_combined_moodle.html`. Those are regenerated by
`pipeline/finalize_module.py --module courses/<course>/module-N-he` after
translation finishes. Slug names are preserved unchanged — the Hebrew
lesson file at index 1 has the same filename as its English counterpart.

## Translation scope

### Translate (learner-facing)

- All prose inside `<p>`, `<li>`, `<td>`, `<th>` elements.
- All headings: `<h1>`, `<h2>`, `<h3>`.
- Callout body text inside `<div class="callout ...">`, including the
  leading `<strong>Note:</strong>` / `<strong>Warning:</strong>` /
  `<strong>Key:</strong>` markers (translate the label too).
- `<figcaption>` text.
- The breadcrumb at the top of every lesson:
  `<p class="breadcrumb">Module N / Lesson K</p>` →
  `<p class="breadcrumb">מודול N / שיעור K</p>`.
- The learning-objectives intro line ("By the end of this lesson you will
  be able to:") and every list item under it.
- The "Key Takeaways" header and its bullets.
- The module-overview body's `meta` line (estimated duration, lesson count,
  quiz info) and every inline-styled lesson summary card.
- `data-description="..."` attribute on `<div class="image-needed">`
  elements (this text is shown to the learner as a placeholder caption).
- The `<span>📷 Image needed: ...</span>` text inside the same div.
- Inside `<svg>`: every `<text>` element's text content, every `<title>`
  element, every `<desc>` element.
- Inside quiz XML: the text content of every `<text>` element wrapped in
  a `<![CDATA[ ... ]]>` block — i.e. the `questiontext`, the
  `generalfeedback`, and each `<answer>`'s text. HTML tags inside the
  CDATA (`<p>`, `<strong>`, `<br>`) are preserved; translate their text
  content.

### Do NOT translate (verbatim preservation)

- CSS class names — `class="ims-lesson"`, `class="callout callout-note"`,
  etc.
- The full `<style>` block at the top of every fragment.
- Inline `style="..."` declarations, including hex color codes inside them.
- Hex color codes anywhere — `#185FA5`, `#0F6E56`, etc.
- SVG attributes: `fill`, `stroke`, `viewBox`, `x`, `y`, `width`,
  `height`, `d`, `points`, `transform`, `font-size`, `font-family`.
- Inside quiz XML: the `<name><text>L1-Q01 — short title</text></name>`
  block. The `L1-Q01` label is an internal Moodle identifier — preserve
  verbatim, including its `— short title` suffix.
- `fraction="100"` and `fraction="0"` attributes on `<answer>` elements.
- `<single>true</single>`, `<shuffleanswers>true</shuffleanswers>`,
  `<defaultgrade>1</defaultgrade>`, and any other quiz toggle elements.
- `format="html"` attributes anywhere.
- File names and slugs (the Hebrew `01_<slug>_moodle.html` has the same
  slug as its English counterpart).
- `module_structure.json` and `_extraction.json` — copied byte-for-byte.

## RTL conventions

For every translated lesson body and the module overview, change the
wrapper from:

```html
<div class="ims-lesson">
```

to:

```html
<div class="ims-lesson" dir="rtl" lang="he">
```

That single change is the entire RTL contract for v1. Do not modify
`config/design_system.css`. Do not introduce a separate
`rtl_overrides.css`. The design system's CSS uses physical properties
(`border-left`, `padding-left`) in a few places — under RTL these will
visually flip in some respects (the callout's left accent stripe will sit
on the right edge, which is correct for Hebrew) and not in others (the
bullet padding inside inline-styled overview cards will look slightly off
because `padding-left:1.4rem` doesn't flip). This is acceptable for v1
and is documented under "Known limitations" below.

`lang="he"` ensures correct browser hyphenation, font selection, and
screen-reader pronunciation. `dir="rtl"` sets the directional context
for everything inside the wrapper.

## Glossary handling

The bilingual glossary lives at [hebrew_glossary.md](hebrew_glossary.md).
Two groups:

1. **Acronyms preserved in Latin script** — ICAO, WMO, METAR, TAF,
   SIGMET, hPa, QNH, etc. Standard Israeli aviation/meteorology practice
   keeps these untransliterated.
2. **Translated terms** — runway, cloud base, turbulence, jet stream,
   etc., with the agreed Hebrew rendering.

Rules for the translator agent:
- Consult the glossary for every technical term encountered.
- Use the listed Hebrew rendering consistently across the entire module.
- For acronyms in group 1, leave the Latin-script form in place.
- For a technical term not in the glossary, render a best-guess Hebrew
  and append `(English term)` on the first occurrence in each lesson.
  Record the proposal in the manifest under `new_glossary_proposals`.
  Do not block on missing entries.

Rules for the editor agent:
- Flag any English term that has two different Hebrew renderings inside
  the same module as `glossary_consistency / warning`.
- Flag any glossary entry whose English term appears in the source but
  whose Hebrew form does not appear in the translation as
  `glossary_consistency / warning`.

## `_translation_manifest.json` schema

Written by the translator agent to the root of the Hebrew module folder
after every file in the module has been processed. Always overwrite on
re-runs; the previous version is archived to
`.archive/manifest_<utc_timestamp>.json` before overwrite.

```json
{
  "schema_version": "1.0",
  "translator_model": "claude-opus-4-7",
  "generated_at_utc": "2026-05-19T14:01:08Z",
  "source_module": "courses/aviation-weather/module-1",
  "translation_module": "courses/aviation-weather/module-1-he",
  "files": [
    {
      "source_path": "lessons/01_international_regulatory_frameworks_moodle.html",
      "target_path": "lessons/01_international_regulatory_frameworks_moodle.html",
      "sha256_of_source": "ab12...ef",
      "translated_at_utc": "2026-05-19T14:00:22Z",
      "glossary_terms_applied": ["ICAO", "WMO", "SARPs", "transition altitude"],
      "new_glossary_proposals": [
        {
          "english": "regional association",
          "hebrew_proposal": "ארגון אזורי",
          "notes": "Inferred from WMO context; suggest SME review."
        }
      ],
      "warnings": [
        "SVG flow-direction left LTR per spec; labels translated in place."
      ]
    }
  ],
  "summary": {
    "files_translated": 9,
    "files_copied_verbatim": 2,
    "glossary_proposals": 3,
    "warnings": 7
  }
}
```

## `review.json` schema

Written by the editor agent (or augmented by `validate_translation.py`)
to the root of the Hebrew module folder. Always overwrite; archive prior
versions to `.archive/review_<utc_timestamp>.json` before overwrite.

```json
{
  "schema_version": "1.0",
  "editor_model": "gemini-3-pro",
  "generated_at_utc": "2026-05-19T14:33:21Z",
  "source_module": "courses/aviation-weather/module-1",
  "translation_module": "courses/aviation-weather/module-1-he",
  "summary": {
    "files_reviewed": 9,
    "error_count": 0,
    "warning_count": 2,
    "info_count": 4
  },
  "issues": [
    {
      "file": "lessons/01_international_regulatory_frameworks_quiz.xml",
      "locator": { "type": "quiz_question_id", "value": "L1-Q02" },
      "severity": "error",
      "category": "quiz_correctness",
      "produced_by": "gemini-3-pro",
      "english_excerpt": "The World Meteorological Organization (WMO)",
      "hebrew_excerpt": "ארגון התעופה הבינלאומי האזרחי (ICAO)",
      "message": "The fraction=\"100\" answer in Hebrew translates to ICAO, but the English correct answer is WMO. Moodle will mark the wrong option correct.",
      "suggested_fix": "Replace the Hebrew fraction=\"100\" answer text with the translation of the English correct answer, and verify no other answer accidentally became correct."
    }
  ]
}
```

### Field definitions

- `file` — path relative to the Hebrew module root.
- `locator.type` — one of `xpath`, `line_range`, `quiz_question_id`.
- `locator.value` — an XPath expression, a `"start-end"` line range, or
  a `L<n>-Q<NN>` question identifier.
- `severity` — `error`, `warning`, or `info` (see rubric below).
- `category` — one of the values in the table below.
- `produced_by` — `"python"` (from `validate_translation.py`) or the
  model name (from the Gemini editor). Lets a human tell which layer
  flagged what.
- `english_excerpt` / `hebrew_excerpt` — short quoted text for context.
  May be `null` when the issue is about structure/presence rather than
  content.
- `message` — plain-English explanation. Audience: the project owner,
  who is not a developer. Avoid jargon.
- `suggested_fix` — actionable instruction, or `null` if no fix is
  obvious. The translator agent reads these on re-runs to know what to
  redo.

---

## Severity and category rubric

### Severity

| Severity | Meaning | Examples |
|----------|---------|----------|
| `error` | Breaks Moodle import, breaks structure, or loses learner-facing correctness. Must fix before upload. | Missing CDATA wrapper; correct answer mistranslated; element count mismatch. |
| `warning` | Violates a spec rule or degrades the learner experience but doesn't break parsing. | Inconsistent glossary term; missing `dir="rtl"` on one wrapper; SVG label left in English. |
| `info` | Style or fluency suggestion. Safe to ignore for v1. | Slightly literal calque; minor wording choice. |

### Category

| Category | What it covers |
|----------|----------------|
| `structural_parity` | Element counts don't match between source and translation. |
| `hex_preservation` | Hex color codes differ between source and translation. |
| `css_class` | CSS class names differ. |
| `cdata_integrity` | CDATA blocks split, unwrapped, or count mismatch. |
| `rtl_markers` | `dir="rtl"` or `lang="he"` missing or misplaced on `.ims-lesson`. |
| `residual_english` | Unexpected English text in Hebrew prose. |
| `glossary_consistency` | Same English term rendered as two different Hebrew forms. |
| `hallucination` | Hebrew content with no English counterpart. |
| `quiz_correctness` | The `fraction="100"` Hebrew answer is not the translation of the English correct answer. |
| `svg_content` | SVG attributes modified, or SVG text left untranslated. |
| `fluency` | Hebrew reads as a literal calque rather than idiomatic professional usage. |
| `file_presence` | A file expected in the Hebrew tree is missing, or the manifest is missing/malformed. |

## Quiz XML translation rules

- Preserve the XML structure exactly. Same nesting, same element order,
  same attributes, same toggle values.
- Translate only the text inside `<![CDATA[ ... ]]>` blocks.
- Inside the CDATA, HTML tags (`<p>`, `<strong>`, `<br>`, `<em>`) are
  preserved as-is. Translate the text content between the tags.
- Never modify `<name><text>L<n>-Q<NN> — ...</text></name>`. The label
  and its short-title suffix stay in English.
- Never modify `fraction="100"` or `fraction="0"`. The correct answer
  stays the same answer; only its text changes.
- If the translated Hebrew text would contain the literal sequence
  `]]>`, split the CDATA into two blocks: `<![CDATA[...]]]]><![CDATA[>...]]>`.
  This is extremely rare; flag it in the manifest if it occurs.

---

## SVG translation rules

- Translate `<text>` element content, `<title>` element content, and
  `<desc>` element content.
- Never modify `fill`, `stroke`, `viewBox`, `x`, `y`, `width`, `height`,
  `d`, `points`, `transform`, `font-size`, `font-family`, `text-anchor`,
  or any numeric attribute.
- Never introduce `var(--xxx)` into any SVG attribute — `finalize_module.py`
  does not scrub these and Moodle will render them as black.
- For v1, do not mirror SVG layouts. A four-step English flowchart
  arranged left-to-right keeps its left-to-right layout; only the labels
  inside are translated. A Hebrew reader following visual flow direction
  will read the steps in reverse — this is a known limitation, documented
  below, and addressed by re-numbering or providing a mirrored version in
  v2.
- If an SVG `<text>` mixes Hebrew prose with Latin acronyms (e.g. "תקני
  ICAO"), prefer to push the acronym to a parenthetical at the end:
  "תקנים (ICAO standards)". SVG 1.1 has no `dir` attribute and bidi
  rendering inside SVG `<text>` is inconsistent across Moodle's HTML
  editor.

## What gets regenerated by `finalize_module.py`

The translator agent **must not** produce these files in the Hebrew
module folder — `pipeline/finalize_module.py` regenerates them when run
against `module-N-he/`:

- `module_combined_moodle.html` — built by concatenating overview +
  every lesson fragment, deduping the `<style>` block, and adding a
  table of contents.
- `module_quiz_all_questions.xml` — built by combining per-lesson quiz
  XMLs.
- `README.md` — upload instructions, written from a template. The
  README stays in English (teacher-facing scaffolding); the runbook in
  it covers uploading the Hebrew combined page.
- `IMAGES_TO_SOURCE.md` — regenerated if any `image-needed`
  placeholders remain.

`finalize_module.py` is module-folder-agnostic. It does not parse
content; it works on the file shape. The Hebrew folder follows the same
shape as the English folder, so the script runs unmodified.

---

## Re-run policy

- The translator agent **always overwrites** the Hebrew tree. Prior
  `_translation_manifest.json` is archived to
  `.archive/manifest_<utc_timestamp>.json` before overwrite.
- The editor agent **always overwrites** `review.json`. Prior file is
  archived to `.archive/review_<utc_timestamp>.json`.
- Both agents create `.archive/` if absent.

This gives traceability without bloating the live folder. After a few
runs the archive can be cleaned up by hand.

## Known limitations (v1)

- **RTL bullet padding on inline-styled overview cards** — the lesson
  fragments inherit RTL behavior from the design-system CSS, but the
  module overview's inline-styled lesson cards use `padding-left:1.4rem`
  on their `<ul>` elements. Under RTL the bullets sit on the wrong side.
  Visually minor; readable. Fix in v2 by switching to
  `padding-inline-start`.
- **SVG flow direction stays LTR** — a four-step English flowchart with
  Hebrew labels reads stage 4 → stage 1 to a Hebrew reader who follows
  visual flow. Acceptable for a professional audience that reads the
  caption first. Fix in v2 with either re-numbered SVGs or per-language
  mirrored copies.
- **Hebrew font fallbacks** — the lesson CSS uses system-font stacks
  which resolve to fonts with Hebrew glyphs on macOS, Windows, and most
  Linux desktops. The target Moodle instance must be verified. If
  glyphs render as boxes, the fix lives in `config/design_system.css`
  (add "Arial Hebrew", "David", etc. to the fallback chain), not in
  translation output.
- **Manual handoff in Antigravity** — the two agents do not auto-trigger
  each other in the stock Manager view. The handoff prompt in
  `prompts/translate-to-hebrew.md` documents the human click sequence.

## Common mistakes to avoid

- **Forgetting `dir="rtl" lang="he"` on the wrapper.** Without it, the
  whole fragment renders left-to-right inside Moodle.
- **Translating CSS class names or hex codes.** Both are structural;
  both must survive translation byte-for-byte.
- **Modifying `<name>L<n>-Q<NN></name>` quiz labels.** Moodle uses these
  as internal identifiers. Touching them re-orders or duplicates the
  question bank on import.
- **Swapping the correct answer with a distractor on translation.** The
  most dangerous failure mode. The `fraction="100"` Hebrew text must be
  the translation of the English `fraction="100"` text, not a different
  answer.
- **Breaking CDATA wrappers.** Translated Hebrew that happens to
  contain `]]>` (rare) splits the block; if you don't split it
  intentionally, Moodle's import fails.
- **Introducing `var(--xxx)` into an SVG attribute during a "minor"
  cleanup.** Same rule as the English pipeline: SVGs use literal hex
  codes only. Never `var(--anything)` inside SVG.
- **Producing `module_combined_moodle.html` or `README.md` yourself.**
  Those are regenerated by `finalize_module.py`. If you write them, you
  fight the pipeline.
