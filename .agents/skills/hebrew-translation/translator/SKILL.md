# Translator — Layer 1

You translate a completed English IMS course module into Hebrew. You do
not invent content. You do not change structure. You produce a Hebrew
mirror of the source folder, file-for-file.

## Read first

Three files, in order, before touching anything:

1. [`docs/hebrew_translation_spec.md`](../../../../docs/hebrew_translation_spec.md) — the contract. Translate / don't-translate lists, manifest schema, RTL rules, quiz and SVG rules. This is your source of truth.
2. [`docs/hebrew_glossary.md`](../../../../docs/hebrew_glossary.md) — bilingual terms. Use the listed Hebrew rendering for every term in Group 2; preserve every Group 1 acronym in Latin script.
3. [`docs/lesson_spec.md`](../../../../docs/lesson_spec.md) — the English output contract. You preserve this shape exactly in Hebrew.

If anything in this skill conflicts with the spec, the spec wins.

## Input

You are invoked against a single module folder:

```
--source-module courses/<course>/module-N
```

For example: `courses/aviation-weather/module-1`.

## Output

Write everything to the sibling folder `<source-module>-he/`:

- **Translate** these files (one Hebrew counterpart per English file,
  same filename, same slug):
  - `00_module_overview_moodle.html`
  - `lessons/NN_<slug>_moodle.html` (one per lesson)
  - `lessons/NN_<slug>_quiz.xml` (one per lesson)
- **Copy verbatim** (byte-for-byte, no edits):
  - `module_structure.json`
  - `_extraction.json`
  - `lessons/Images/` directory (copy or symlink — translation does not
    touch image files)
- **Write last** (after every file above is in place):
  - `_translation_manifest.json` at the root of the Hebrew module folder
- **Do NOT produce**:
  - `README.md`, `IMAGES_TO_SOURCE.md`, `module_combined_moodle.html`,
    `module_quiz_all_questions.xml`. These are regenerated by
    `pipeline/finalize_module.py` after you finish.

## Translation scope

### Translate (learner-facing)

- All text inside `<p>`, `<li>`, `<td>`, `<th>`, `<h1>`, `<h2>`, `<h3>`,
  `<figcaption>`, `<strong>`, `<em>`.
- Callout body text inside `<div class="callout ...">`, including the
  leading label (`<strong>Note:</strong>` → `<strong>הערה:</strong>`).
- Breadcrumbs: `<p class="breadcrumb">Module N / Lesson K</p>` →
  `<p class="breadcrumb">מודול N / שיעור K</p>`.
- Learning objectives intro line and every list item.
- Module overview's `meta` line (estimated duration, lesson count, quiz
  description) and every inline-styled lesson summary card.
- `data-description="..."` attributes on `<div class="image-needed">`.
- SVG `<text>`, `<title>`, `<desc>` content.
- Quiz: every `<text>` inside `<![CDATA[ ... ]]>` — i.e. `questiontext`,
  `generalfeedback`, and each `<answer>`'s text. HTML tags inside the
  CDATA stay; translate the text between them.

### Preserve verbatim (do NOT translate)

- CSS class names — `class="ims-lesson"`, `class="callout callout-note"`,
  etc.
- The full `<style>` block at the top of every fragment.
- Inline `style="..."` declarations, including hex codes inside them.
- Hex color codes anywhere — `#185FA5`, `#0F6E56`, `#534AB7`, etc.
- SVG attributes — `fill`, `stroke`, `viewBox`, `x`, `y`, `width`,
  `height`, `d`, `points`, `transform`, `font-size`, `font-family`,
  `text-anchor`. Any numeric attribute. Never introduce `var(--xxx)`.
- Quiz `<name><text>L1-Q01 — short title</text></name>` blocks. The
  `L<n>-Q<NN>` label and its `— short title` suffix stay English.
- `fraction="100"` and `fraction="0"`. The correct answer stays the same
  answer; only its text changes.
- `<single>true</single>`, `<shuffleanswers>true</shuffleanswers>`,
  `<defaultgrade>1</defaultgrade>`, `format="html"`.
- File names and slugs.

## RTL adjustment

Exactly one change to every translated lesson body and the module
overview. Find the wrapper:

```html
<div class="ims-lesson">
```

Replace with:

```html
<div class="ims-lesson" dir="rtl" lang="he">
```

That is the entire RTL contract. Do not modify `config/design_system.css`.
Do not introduce a separate `rtl_overrides.css`. Do not change any class
name. Do not add inline `style` attributes for RTL.

## Terminology

For every technical term, consult the glossary:

- **Group 1 (acronyms)** — leave in Latin script. ICAO, WMO, METAR, TAF,
  SIGMET, hPa, QNH, etc. Do not transliterate.
- **Group 2 (translated terms)** — use the "preferred" Hebrew rendering.
  Use it consistently across the entire module. The editor agent flags
  inconsistencies as `glossary_consistency / warning`.

For a technical term **not** in the glossary:

1. Render a best-guess Hebrew.
2. On the first occurrence in each lesson, append `(English term)` in
   parentheses so the reader can verify.
3. Record the proposal in `_translation_manifest.json` under that file's
   `new_glossary_proposals` array.
4. Do not block — keep going.

## SVG handling

For each `<svg>`:
- Translate `<text>` element content, `<title>`, and `<desc>`.
- Never modify `fill`, `stroke`, `viewBox`, or any numeric attribute.
- Never introduce `var(--xxx)` into an attribute.
- Do **not** mirror the SVG layout. A four-step English flowchart
  arranged left-to-right keeps its left-to-right layout; only labels
  are translated. Flag this in the file's `warnings` array in the
  manifest: `"SVG flow-direction left LTR per spec; labels translated
  in place."`
- If an SVG `<text>` mixes Hebrew with a Latin acronym, push the
  acronym to a parenthetical at the end of the label: prefer
  `"תקנים (ICAO)"` over `"ICAO תקנים"` — SVG bidi rendering is
  inconsistent across Moodle's HTML editor.

## Quiz XML handling

- Preserve the XML structure exactly. Same nesting, same attributes,
  same toggle values.
- Translate **only** the text inside `<![CDATA[ ... ]]>` blocks.
- HTML tags inside the CDATA (`<p>`, `<strong>`, `<br>`) stay; translate
  the text between them.
- Never modify `<name><text>L<n>-Q<NN> — ...</text></name>`.
- Never modify `fraction="100"` / `fraction="0"`. The
  `fraction="100"` Hebrew answer must be the translation of the English
  `fraction="100"` text — not a different answer. This is the most
  dangerous failure mode in the whole pipeline.
- CDATA edge case: if your Hebrew translation contains the literal
  sequence `]]>` (extremely rare — only if you're quoting a code
  snippet), split the block into
  `<![CDATA[...]]]]><![CDATA[>...]]>` and flag it in `warnings`.

## Manifest

Write `_translation_manifest.json` at the root of the Hebrew module
folder. Schema documented in [`docs/hebrew_translation_spec.md`](../../../../docs/hebrew_translation_spec.md#_translation_manifestjson-schema).

If a manifest already exists from a previous run, archive it first:

```
<module-N-he>/.archive/manifest_<utc_timestamp>.json
```

Create `.archive/` if absent. Then overwrite the live manifest.

## Hard rules — never violate

- Never change HTML element counts, structure, or nesting.
- Never modify CSS class names.
- Never modify hex color codes.
- Never modify SVG attributes (other than translating `<text>` /
  `<title>` / `<desc>` content).
- Never break CDATA wrappers.
- Never modify quiz `<name>` labels.
- Never modify `fraction=` markers.
- Never rename files or change slug names.
- Never produce `README.md`, `IMAGES_TO_SOURCE.md`, or
  `module_combined_moodle.html`. Those are not your responsibility.

## Order of operations

1. Read the spec, the glossary, and the source module folder.
2. For each lesson HTML file, produce the Hebrew counterpart.
3. For each quiz XML file, produce the Hebrew counterpart.
4. Translate the overview body fragment.
5. Copy `module_structure.json`, `_extraction.json`, and `Images/`
   verbatim.
6. Write `_translation_manifest.json` last, after every file is in
   place. The manifest must reflect every file actually written.
7. Print a one-line summary: files translated, glossary additions
   proposed, warnings.

## When to stop and ask

You do not stop on missing glossary entries — propose a Hebrew and
flag it. You do stop and ask the user if:

- The source folder is missing files that the spec requires (e.g.
  no `module_structure.json`, no `lessons/` directory).
- You encounter an HTML structure that doesn't match the spec (e.g. a
  fragment without an outer `.ims-lesson` wrapper).
- A quiz file has zero `fraction="100"` answers, or more than one. That
  is a pre-existing bug in the English source; flag it.

In all other cases, keep going.
